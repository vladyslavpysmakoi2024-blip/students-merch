# Як робити push / pull request на гілку main для успішного проходження Workflows
1. Перейдіть в терміналі в теку `...\backend`.
2. Оновіть файл залежностей `requirements.txt`, якщо ви додали нову необхідну для роботи бібліотеку через 
`pip freeze > requirements.txt`(**! Команда додає всі ваші бібліотеки наявні у `.venv`, якщо у вашому `.venv` є лишні
бібліотеки, тоді бажано робити це через `pip install pipreqs` -> `pipreqs . --force`**)
3. (Для цього кроку необхідна бібліотека `ruff` -> `pip install ruff`) Виконайте команду `ruff format .` (опціонально: `ruff check --fix .`), після цього ваші файли буде
відформатовано до загального вигляду.
4. Зробіть push / pull request.
5. Перегляньте результат Workflows, якщо наявні помилки, то перегляньте їх у `GitHub -> Actions -> All Workflows -> 
Оберіть Action де є помилка -> Summary і знизу є Annotations, для більш детального оголяду можете переглянути в All Jobs логі
де детально пише всі помилки` і виправте їх.
6. Зробіть після виправлення усіх помилок новий push і пройдіть знову перевірку, якщо знову появились помилки
перейдіть до пункту 5.

P.S.: Якщо ви не розумієте що за помилку видає Pylint, Ruff або інше, AI (У всякому разі Gemini непогано пояснює
як їх виправляти) розкаже чому і навіщо потрібно це виправити. Workflows працюють лише на гілку main (push команда), бо вони мають
обмеження місячне, яке бажано лишній раз не витрачати. Pull request виконує перевірку незалежно від гілки.
